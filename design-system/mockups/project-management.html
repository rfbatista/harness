Projects list and project settings

Mockups for task "Project management", built with the real design-system CSS (design-system/css). Each screen is shown at 375px in the light and dark themes. On wider screens the same markup sits in the app shell beside the task rail.

  • /projects: every project with its live counts. J/K move, Enter opens, S opens settings, N new project, / filter.
  • /projects/{project}/settings: name and directory, ignored paths, links to Repositories, and the danger zone.

Revision 2: the real pages

Screenshots from the end-to-end test on the real server (internal/adapter/in/web/projects_e2e_test.go) at 375px. What differs from the approved mockup below:

  • The top bar shows Projects in place of New project (as decided in review). New project is on /projects.
  • Project names are links without an underline; they underline on hover.
  • The delete refusal names each session by its agent (or “a session”) with a link to its task and a short session id. The server's details carry no task title, so the mockup's task names are not shown.
  • Settings: Undo appears only when there are unsaved edits; “Saved.” confirms a save next to the button.
  • Last activity reads “active 2m ago” (the shared short form) where the mockup wrote “2 min ago”.
  • At phone width the project's task rail sits above the settings, as on every project page.
