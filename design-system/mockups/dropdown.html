Dropdown — listbox, combobox, menu

The scripted variants of the dropdown catalogue, drawn on the design system's tokens. Every one starts from the same closed control as the native select (32px, 5px, line-control edge, the stroked chevron) and opens the same floating .popup: raised, line-strong edge, 8px radius, Float shadow, 4px from its trigger and at least as wide. Inside, 32px options: the one the keys are on gets the hover veil and a hairline ring; the chosen one the selection wash and a signal check. Below 48rem the popup becomes a bottom sheet with 44px rows.

Which dropdown should I use?

Ask in order; take the first yes. The lightest variant that does the job wins. (From the UX document; this is the card the README and DESIGN.md will carry.)

  1. Does picking run a command (delete, copy link, move…) rather than set a value the page keeps?4 · Menu button
  2. Is picking a step on its own: opened from a button, from a long list, focus should leave the page?5 · Picker dialog
  3. 2–5 options the person should see at once, or several values from ≤ 6?Radio / checkboxes
  4. More than ~15 options, typed by name, loaded by query, several values, or free text allowed?3 · Combobox
  5. Options need a second line, a status dot, a badge, or the value must be clearable?2 · Listbox select
  6. Otherwise: a short list of plain values. Also the default for templ pages that must work without JavaScript.1 · Select

2 · Listbox select

A button that opens rich options; a hidden native <select> stays the source of truth. Closed, it is indistinguishable from variant 1 except for what it can show: an icon or a status dot before the value, and a clear button when the value may be empty.

2 · Listbox select, open

Rich options (icon, label, one-line description, trailing meta); groups with the quiet 12px heading and status dots that keep their word; a long list that stops at 8½ rows so the half row says "scroll"; opening upward when there is no room below; loading, empty and error said in a sentence, never a blank box.

3 · Combobox

An input inside the same box, with a toggle (▾) and a clear (×). It filters as you type: the match is bold and underlined, never highlighted with colour. Several values become chips before the input; free text, when allowed, is always the last option so Enter never loses it.

4 · Menu button

Commands, not values. The trigger is a normal .button (secondary with a small chevron, or an icon-only ghost ⋯); it stays pressed while the menu is open. Items are 32px with an optional icon and a right-aligned kbd; separators group them; the destructive one is last and red; a disabled item stays readable and says why. A "move to" list shows where the thing is now with a signal dot.

Phone (below 48rem): sheets

The native select keeps the OS picker. The scripted variants open as a bottom sheet over a scrim: the field's label as the title, a Close (no change), 44px rows. The combobox's sheet is tall and puts its input at the top, so the on-screen keyboard never covers the list. The menu becomes an action sheet.

5 · Picker dialog

Already built: the command palette's <dialog> used as a chooser (picker.js + PickerDialog). Its options take the same rich option row as the popup above, so a feature that outgrows a dropdown moves to it without a visual jump. Nothing new to design here.
