# Harness design system: CUBE CSS

The web UI's CSS follows [CUBE CSS](https://cube.fyi): **C**omposition,
**U**tility, **B**lock, **E**xception, built on top of a strong global layer.
CUBE extends CSS rather than fighting it: the cascade and inheritance do most
of the work, so by the time you reach a block there is little left to write.

The visual spec (colors, type, components, do's and don'ts) is [`DESIGN.md`](../DESIGN.md).
This file is about **where CSS goes and how to write it**.

```
design-system/
  tokens.json            design tokens: the single source of truth
                         (generated by `go run ./cmd/designtokens`: tokens.json →
                          css/global/tokens.css + css/utilities/tokens.css)
  specimen.html          every block, plus the Sessions screen as a worked example
  css/
    index.css            entry point: declares the layers, imports everything
    global/              reset.css, tokens.css (generated), global.css
    compositions/        flow, cluster, repel, sidebar, switcher, grid, wrapper, frame
    utilities/           tokens.css (generated), visually-hidden, truncate, region, divide, flex-item
    blocks/              one file per block, exceptions inside it
```

Cascade layers pin the CUBE order no matter the selector specificity:

```css
@layer reset, global, compositions, utilities, blocks;
```

## Global: style elements, not classes

`global/global.css` styles HTML itself: type, links, `code`, `kbd`, form
controls (`input`, `select`, `textarea`, checkboxes), tables, focus, reduced
motion. This is the minimum viable experience, and most of the UI. A plain
`<input>` or `<kbd>` is already correct; you never add a class to make one look
like the system.

Reach here first. If every instance of an element should look one way, it is a
global style, not a block.

## Compositions: layout skeletons

High-level, content-agnostic layout. They decide how elements sit next to each
other and nothing else: **no color, no type, no decoration**.

| Class | Job | Tune with |
|---|---|---|
| `flow` | vertical rhythm between children | `flow-space-*` |
| `cluster` | wrapping inline group | `gutter-*`, `data-align`, `data-justify` |
| `repel` | two groups pushed apart | `gutter-*` |
| `with-sidebar` | intrinsic side + fluid main | `gutter-*`, `--sidebar-target`, `data-side="end"` |
| `switcher` | row ↔ column at a container threshold | `gutter-*`, `--switcher-threshold` |
| `grid` | auto-filling tracks | `gutter-*`, `--grid-min` |
| `wrapper` | centred, measured column | `--wrapper-max`, `--wrapper-gutter` |
| `frame` | full-height column, `[data-scroll]` child scrolls | none |

Each composition sets its own default `--flow-space` / `--gutter` on itself,
and the token utilities (a later layer) override it. A nested composition
therefore never inherits its parent's spacing. `flow` uses `gap` rather than
`> * + *` margins for the same reason.

## Utilities: one job each

A utility applies one property (or a tight group) and moves repetition from
CSS into HTML. **Design-token utilities are generated** from `tokens.json`:

| Prefix | Property | Tokens |
|---|---|---|
| `color-*` | `color` | ink, ink-muted, ink-faint, signal, attention, danger, success |
| `bg-*` | `background` | canvas, panel, raised, sunken |
| `font-*` | `font-family` | sans, mono |
| `text-*` | `font-size` | xs … 2xl |
| `weight-*` | `font-weight` | regular, medium, bold |
| `leading-*` | `line-height` | tight, snug, normal |
| `flow-space-*`, `gutter-*` | composition spacing | 3xs … 3xl |
| `pad-*`, `pad-inline-*`, `pad-block-*` | padding | 3xs … 3xl |

Hand-written utilities live one per file: `visually-hidden`, `truncate`,
`region`, `divide-top|bottom|end`, `grow`, `shrink-0`, `push-end`.

Utilities never use `!important`. Because blocks come after utilities, **a
block's own declarations win over a utility on the same element**. Use
utilities for what the block leaves open. If you have to fight a block, write
an exception.

## Blocks: small, contextual components

A block styles one UI context (`button`, `row`, `nav`, `transcript`, …) on top of
everything above it. Rules:

- **One file per block** in `css/blocks/`, at most 80–100 lines. If a block
  grows past that or solves two problems, split it.
- **Native CSS nesting**, with the block class as the safety net. Inside it, target
  elements and short element classes directly: `.nav a`, `.toolbar h1`,
  `.row .title`, `.pane > header`. No BEM `__element` names.
- Use the **child combinator** where the block can contain other blocks
  (`.pane > header`, `.transcript > .line`), so styles never leak into a nested block.
- Prefer **semantic and ARIA hooks** over classes: `[role="tab"]`,
  `[role="option"]`, `<time>`, `<header>`.
- Read only **semantic tokens** (`var(--color-panel)`, `var(--space-m)`). A raw
  value in a block is a missing token.
- Private, per-block custom properties start with an underscore: `--_tone`, `--_bg`.

## Exceptions: data attributes, inside the block

An exception is a deviation from a block: a variant or a state. It is written
**inside the block's own file**, keyed on a `data-*` or ARIA attribute,
**never a class**:

```css
.button {
  /* … */
  &[data-variant="primary"] { --_bg: var(--color-signal); }
  &[aria-busy="true"] { /* spinner */ }
}
```

```html
<button class="[ button ]" data-variant="primary" aria-busy="true">Save</button>
```

Vocabulary in use: `data-variant`, `data-size`, `data-icon`, `data-tone`,
`data-state`, `data-signal`, `data-kind`, `data-attention`, `data-dense`,
`data-inline`, `data-dot-only`, plus `aria-selected`, `aria-current`,
`aria-invalid`, `aria-busy`, `disabled`. If an exception changes a block beyond
recognition, it is a new block.

## Class grouping in markup

Group classes with square brackets in CUBE order: the primary block, other
blocks or compositions, standard utilities, then design-token utilities:

```html
<div class="[ list ] [ divide-end ]" role="listbox">
<div class="[ cluster ] [ divide-top ] [ pad-block-s pad-inline-l ]">
<section class="[ flow ] [ flow-space-m ]">
<input class="[ grow ] [ font-mono text-sm ]">
```

Elements inside a block use their short class alone: `class="[ title ]"`.

## Adding things

- **A token:** edit `tokens.json`, run `go run ./cmd/designtokens`.
  `go test ./cmd/designtokens` (part of `make check`) fails when the generated files are stale.
  Never edit `global/tokens.css` or `utilities/tokens.css` by hand.
- **A token utility:** add an entry to `tokens.json` → `utilities` (`prefix`,
  `property`, `group`, optional `only`) and regenerate.
- **A layout:** first check whether a composition plus a custom property does it.
  Add a new composition only for a genuinely new layout relationship.
- **A component:** a new file in `css/blocks/`, imported in `index.css` under
  `/* Blocks */`; add it to `specimen.html` and to DESIGN.md §5.
- **A state or variant:** an exception inside the existing block file.

## Delivery

`index.css` uses `@import` so the source stays one file per concern. Whatever
serves the web UI bundles it into a single stylesheet: `go run ./cmd/webbuild`
(esbuild's Go API, see `docs/WEB.md`). The layer order survives bundling. Fonts
(Atkinson Hyperlegible Next and Mono) should be self-hosted as woff2; the
specimen loads them from Google Fonts for convenience.
