What this shows

The repository code page reads a repository at a ref, chosen from the source bar's native select (branches, then tags; a pasted hash works too), the way the history page does. It has Files and Map but no Changes: a ref has nothing uncommitted. The source bar shows the commit the ref resolved to. Every later read pins that commit, so a branch moving mid-read never mixes two versions. Y rewrites the URL to that commit, the same permalink move GitHub uses.

Find file (T) opens the existing command palette over /api/code/paths: fuzzy match on the path, the match in bold and underlined, the directory faint, the change mark at the end in a session. Past 50,000 paths a last row says the list is cut. Go to line (L) is the same palette with one field, accepting 120 or 120-140. It sets the URL's #L120-L140, scrolls there and targets the lines.

The tree is lazy. A directory being read shows skeleton rows under it, and the open file is selected and scrolled into view on first paint.
