What the session screen's Agent tab is built from today, read from design-system/css/blocks, design-system/specimen.html, DESIGN.md, the session template (internal/adapter/in/web/sessions/page.templ, channel.templ) and the person's screenshot Terminal section print. Read-only inventory: nothing was changed. Rules L1–L6 refer to the project contract Design system ↔ Web UI — session terminal pane layout.

Probable root cause of the clipping (design-system side)

terminal.css pads the element xterm is fitted to. .terminal > .screen has padding: var(--space-s) var(--space-m), and xterm-screen.js calls term.open(container) on that same .screen. FitAddon measures the parent's computed height/width and subtracts only the padding of xterm's own element. With the global box-sizing: border-box reset, the parent's computed size includes its padding, so xterm proposes rows/cols for a box 2×space-s taller and 2×space-m wider than it has. .screen { overflow: hidden } then clips the overflow.

That matches the screenshot exactly: the last row (auto mode on · esc to interrupt) is cut in half at the bottom, and long lines are cut on the right (…3d7da05b/3). This breaks L3.

Fix direction (for the frontend-developer and later for terminal.css): leave the fitted element unpadded, and put the gutter on xterm's element (.screen > .xterm { padding }, which FitAddon does subtract), or on an inner wrapper that xterm opens into. I'm not touching web/src or the CSS until the UX proposal is approved; I'm flagging it to the architect so the frontend-developer can confirm it.

Other layout weaknesses behind L1, L2 and L5

  • Nested scroller. main.frame > .split-view[data-scroll] scrolls (overflow: auto). When the detail column is taller than the viewport the split view scrolls, not the terminal. The screenshot shows that outer scrollbar next to the tab bar. This breaks L1 and L5.
  • The terminal has a minimum height. .screen { min-block-size: 12rem } sits inside a .terminal[data-scroll] that is itself overflow: auto. On short viewports, or when the header grows (status-check row, delete banner, a wrapped toolbar), the terminal block overflows and scrolls as a box. xterm is never told it got smaller.
  • The chrome can shrink. In .frame every child keeps flex-shrink: 1. .tabs has overflow-x: auto, so its automatic minimum height is 0 and it can be squeezed vertically. The header and tabs need flex: none.
  • Two footers. The terminal's 32px .bar (status + window title, the "live ◆" in the screenshot) and the shell's 28px .stream-bar (also "live"). Both show connection status, and together they cost about 60px of terminal height.

What I'll carry into the components once the UX proposal is approved

  • A session header block with a fixed, compact height: title, status, agent and age on one line, and actions on the right with Delete moved into a menu. The status check folds into a small chip/popover so the header height doesn't change when it appears.
  • Tab bar with a right-hand slot for pane tools and the connection word, so the terminal's own bar can go.
  • Terminal block fixed for L3 (unpadded fit target), no minimum height, a single scroller, and overlay states: connecting, reconnecting, ended with Resume, waiting on you.
  • The specimen session screen rebuilt so the contract is visible and testable.
