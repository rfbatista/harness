# web/ — the browser half of the web client

Plain JavaScript ES modules running on Alpine.js (CSP build). Every Alpine
component is registered with `Alpine.data()`. The architecture (modules,
layers, the SSR contract with the templ BFF) is in [`docs/WEB.md`](../docs/WEB.md);
the CSS is [`design-system/`](../design-system/README.md).

```
src/
  main.js                       composition root (real infrastructure)
  shared/                       kernel: domain (errors, feed status), infrastructure
                                (api, feed, storage, clock), presentation (seed,
                                errors, format, shell components), testing
  modules/<module>/
    domain/                     rules + ports.js (the contracts infrastructure fulfils)
    infrastructure/             gateways over /api and SSE, DTO mappers, memory gateway
    presentation/               pages/, components/, view.js, register.js
    testing/                    fixtures, stub API, the port's contract suite
dev/                            pages that run the real modules on the memory gateway
test/                           browser test page; all.js lists every *.test.js
testdata/views/                 fixtures shared with the Go BFF's tests
vendor/                         Alpine and xterm.js, pinned (see vendor/README.md)
third_party/highlightjs/        highlight.js for the code views, pinned and tracked (see its README.md)
third_party/htmx/               htmx for the swap regions, pinned and tracked (see its README.md)
```

## Running it

The Go server serves it (templ pages in `internal/adapter/in/web`):

```bash
make air                  # builds the web client first, then http://127.0.0.1:8080/
make web                  # templ generate + bundle (go run ./cmd/webbuild)
make web-watch            # rebundle on every change, beside `make air`
go test ./internal/adapter/in/web/   # page tests + browser suite + page boot in headless Chrome
```

Without the server, the modules also run as-is from any static server rooted
at the repository (handy for the in-memory dev page):

```bash
python3 -m http.server 8413        # from the repo root
open http://127.0.0.1:8413/web/test/index.html     # unit tests
open http://127.0.0.1:8413/web/dev/task.html   # a task page, in memory
open http://127.0.0.1:8413/web/dev/history.html   # a session's git history and its pull request
```

Disable the browser cache (or use a no-cache server) while editing: modules are
cached aggressively. On the dev page, `window.harness` simulates the server:
`harness.finish("s-port")`, `harness.ask("s-suite")`, `harness.drop()`,
`harness.reconnect()`, `harness.publish("s-feed")`, `harness.promote("art-1")`,
`harness.attach("art-1", "t2")`, `harness.detach("art-1", "t2")`; for a task with an
architect, `harness.report("s-port", "s-arch", "ready_for_review")`,
`harness.reply("s-arch", "s-port", "Rename it.", "changes_requested")` and
`harness.fireCheck("s-port")`; a session's PR badge, `harness.pr.open("ws-port")` and
`harness.pr.state("ws-feed", "merged")`. On the history page, `harness.pr` plays the
server and the host for its workspace: `open({ draft: true })` (another browser or
the server's background check), `state("merged")`, `block("PR_TOOL_UNAVAILABLE")`
(seen on reconnect or when the form opens), `update({ ahead: 0 })`,
`failNext("PR_PUSH_FAILED", "! [rejected] …")`, `slow(4000)`, `echoFirst()`,
`forget()` (the workspace row is gone), and `harness.drop()` / `harness.reconnect()`.

## Adding code

- `test/all.js` is generated by `go run ./cmd/webbuild`; a Go test fails when it is stale.
- Follow the layer rules in `docs/WEB.md`: domain imports nothing outward,
  presentation never imports infrastructure, modules never import each other,
  only `main.js` and `dev/main.js` construct infrastructure.
- Markup binds properties and calls methods; logic lives in the component.

## Swap regions and Alpine components

Two client styles live side by side (ADR 0005); the line between them is the
swap region.

- **A swap region** is a server-owned part of a page that htmx replaces in
  place when a link inside the page is followed: the documents list and viewer,
  a commit's detail. The page's own URL answers `HX-Request` with just the
  region (a fragment response) from the same templ component as the full page.
  Mark it with `shell.SwapRegion(id)` and its links with `shell.SwapLink(id)`;
  every trigger stays a real `<a href>`, so new tabs, reloads and pages without
  JavaScript work as before.
- **Everything else is Alpine:** writes (through the `/api` JSON client), live
  views fed by SSE, terminals, the code browser, the shell's navigation.
- **A swap region never depends on the page seed.** An Alpine component inside
  it may read only data swapped with it: data attributes on its element, or a
  region-local seed (a JSON script inside the region, read by nothing outside
  it). Alpine initialises it again after each swap.
- A new swap region must be read-mostly and already server-rendered;
  otherwise it belongs to Alpine.
- htmx is configured once, in `src/swap-regions.js`, wired from `main.js`
  only: no eval, no `hx-on`, and no script that can run: a fragment holding
  any `<script>` other than `type="application/json"` is never inserted (the
  URL loads as a page). Busy state, scroll, focus on the region's heading, the
  list's highlight and the fall-back to a full load when a swap fails are
  done there for every region, never per page. Back and Forward load the page
  (no history snapshots, which would bring back dead Alpine markup).
